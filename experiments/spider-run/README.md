# Spider-derived schema-pair experiment

This is an exploratory local run on the data committed at `e46d4667fe001ac68cf20593eaa3e2f52accc764` in [Cross-schema-sql-translation](https://github.com/jiatongliU7/Cross-schema-sql-translation). The downloaded data is copied into the project `data/` directory; do not confuse it with the official Spider split. The 182 variants correspond to 20 original databases: train 123 pairs / 14 databases / 3,032 queries, dev 29 / 3 / 925, test 30 / 3 / 1,515. `splits.json` defines level: L1 = no renamed identifier referenced, L2 = one, L3 = two or more. Variants of each database are in the same split.

Five methods were run on all pairs: lexical (no explicit type/FK weight), pretrained SBERT (semantic), fine-tuned SBERT (semantic), fine-tuned + type, fine-tuned + type + FK. The fine-tuned model used the training split only: 2,728 positive pairs before deduplication, 608 after; `all-MiniLM-L6-v2`, 1 epoch, batch size 16, learning rate 0.00002, seed 42. Explicit type weight 0.15 and FK weight 0.3 were fixed in advance and were not tuned on dev. All models share the same AST SQL rewriting and target-side evaluation. Type and FK key-role metadata appear in SBERT description text even in the semantic-only baseline, so this does not test a complete absence of FK information. FK reranking uses a local search; methods with FK weight zero do not use the explicit FK objective.

`summary_test.csv`, `summary_dev.csv`, and `summary_train.csv` report selected-mapping accuracy, renamed-only column accuracy, retrieval Top-1 / Top-3, and target-side SQL execution equivalence. All records are weighted per column or query occurrence, not by independent database. Different variants reuse underlying databases and SQL, so results are correlated. The test set is only 3 base databases, and all table names remain unchanged; 647/940 test column names also remain unchanged. Thus report renamed-only results as well and do not generalize the table accuracy.

`results/<method>_<split>/results.csv` contains overall, level, and JOIN results; `error_analysis.json` and `query_results.json` contain detailed errors and query outcomes. `predictions/<method>/<pair_id>.json` has every generated candidate and mapping. `reference_audit.json` compares original and gold target SQL across the corresponding copied DB instances; `gold_rewriter_audit.json` compares our rewriter using gold mapping against reference SQL on the target DB. Both agree for all 5,472 query instances; this is not proof of semantic equivalence on arbitrary data. No LLM baseline or TPC-H experiment was run.

Model outputs, runtime dependency installation and the model cache are local; do not publish model weights or dataset copies without reviewing repository size and source terms. The official Sentence-Transformers package was installed into a temporary runtime for this run. Reproduction requires Python dependencies from `requirements-neural.txt`, a downloaded SBERT model, and the local dataset. See `docs/HANDOFF.md` for the interface and caveats.
