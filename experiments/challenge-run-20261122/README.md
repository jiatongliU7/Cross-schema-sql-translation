# Challenge mapping experiment

Data: challenge pairs at repository commit `d7058276abdf1cb6c66b9e46605b4dea1f64ac72`; 20 schema pairs, 14 train / 3 dev / 3 test, and 1,034 queries. Challenge variants rename all 80 ordinary tables and 406 of 439 columns. They reuse the same 20 original databases as the standard dataset and do not add independent database diversity.

The existing `models/spider-run-epoch1` model was trained for one epoch on the older standard training pairs, without retraining on challenge data. Its 14 training databases reappear in the challenge train split, so train mappings are not a held-out evaluation. The 3 dev and 3 test base databases did not occur in training. Evaluation is exploratory; the same held-out test databases were evaluated in a previous run, and test-informed tuning or conclusions require care. Pretrained MiniLM and the existing checkpoint were run without new training. Type weight 0.15 and FK weight 0.3 are the previous fixed settings, not tuned on the challenge set. Encoder inputs include type and key roles even in semantic-only baselines.

`predicted_mapping/<method>/<pair_id>.json` contains complete top-level `tables` and `columns` dictionaries for all 20 pairs, formatted for the team's `evaluate_pipeline.py --methods saved --mapping-dir ...`. `predictions/` retains candidates, full mapping and rewritten SQL. `summary.csv` contains dev and test results from the team's evaluator; `evaluation/<method>_<split>/` contains per-pair, per-query, and error records. The evaluator labels the method `saved`, so directory names and `summary.csv` indicate which model produced each mapping.

The official dataset validation script checked all 20 challenge pairs and executed all 1,034 source/reference SQL pairs without detecting mismatches on these data instances; see `data_audit.json`. This does not prove semantic equivalence on all possible databases. Evaluation SQL uses the team's fixed rewriter and evaluator. On test, all methods produced valid mappings and 216 executable SQL queries. Five gold result sets are empty and may yield accidental agreement. SQLite internal table `sqlite_sequence` remains unchanged. Results are query/column micro-averages and cover only 3 test databases, not a general performance guarantee. No LLM or TPC-H baseline was run.
